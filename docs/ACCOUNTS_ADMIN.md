# Beta administration and player account plan

Research checked 2026-11-02. The current service accepts signed EOA and supported smart wallets and derives a stable, 19-character Luanti protocol name from its address. It has admin stats, a recent native player explorer, local username holds and an optional wallet-bound beta invite gate. A local-only ZeroDev email-code lab builds and renders; real provider authentication and public card payment remain unimplemented. Local managed-name activation sets a one-year term and hides expired names. The signed-in wallet panel shows pending, active, unverified and expired terms; renewal checkout remains. Keep the internal character key stable while adding public display names; changing the native key would risk inventories, protection and town ownership.

## Signup choices and account identity

1. **Existing Ethereum wallet:** keep the current nonce/domain/chain-bound Sign-In with Ethereum challenge. After sign-in, let the player select a verified ENS name they control; retain the wallet-derived fallback if they do not own one. The wallet address is the account key; the ENS name is a mutable display alias. An ENS address record pointing at a wallet, or a reverse name, is not by itself proof that the wallet **owns** that ENS name. Verify current ownership/control through the applicable ENS registry path before binding an alias, then recheck after transfer/expiry and on later login. Normalize ENS names with the current ENS rules and prevent two MineMine accounts from claiming the same displayed name. The existing forward-verified reverse lookup is useful for a primary-name suggestion, but does not satisfy the “any ENS name they own” request. A new server verifier now checks exact ENSv2 ownership and active ENSv1 `.eth` registrar/NameWrapper ownership against mainnet; its read-only `vitalik.eth` registrant/manager distinction passed. The wallet account panel now accepts a verified full ENS selection, stores it uniquely, and rechecks it on identity and native tickets. Transfer or expiry clears the stale selection; RPC outages hide it until verification resumes. Injected-wallet Chromium selection passed; a real owner's native nametag proof remains. ENSv1 DNS-import expiry is not yet supported. [ENS ownership and wrapping](https://docs.ens.domains/wrapper/states/) and [ENSv2 readiness](https://docs.ens.domains/web/ensv2-readiness/) make the ownership API a versioned implementation decision.
2. **ZeroDev embedded wallet:** the [current ZeroDev Wallet docs](https://docs.zerodev.app/wallets) describe passkey, social or email authentication that provisions a smart account. This gives the requested conventional, non-extension signup experience, although the resulting account is still an on-chain wallet. These players choose a unique custom MineMine username. ZeroDev's [quickstart](https://docs.zerodev.app/wallets/quickstart) distinguishes EIP-7702 mode, which exposes a user wallet address, from ERC-4337 mode, which exposes a Kernel smart-account address. The MineMine backend now checks deployed [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271) and undeployed [ERC-6492](https://eips.ethereum.org/EIPS/eip-6492) signatures through a matching-chain RPC before issuing a session or game grant; its local-Anvil HTTP proof, including a forged-wrapper denial, passed [foundation run 41390601122](https://github.com/cupOJoseph/minemine/actions/runs/41390601122). A real ZeroDev project and browser account still need end-to-end QA. ZeroDev's [signing guide](https://docs.zerodev.app/smart-accounts/sign-and-verify) recommends the same distinction. Use `7702` on Ethereum Sepolia for the first ZeroDev integration: the current [connector options](https://docs.zerodev.app/wallets/connector-options) make it the default and show `sepolia` as a supported chain, while the [EIP-7702 quickstart](https://docs.zerodev.app/get-started/eip-7702/quickstart) also uses Sepolia. This keeps the account address equal to its EOA address. A real project ID, exact origin allowlist and gas policy are still needed; this is a design choice, not a tested provider login. Test exact account continuity, logout/revocation and MINE/town transactions before enabling this option.
3. **Credit-card scope:** the product now calls for a **single $2 USD initial charge for the ZeroDev-backed account and the first year of its `username.minemine.eth` reservation, with renewal afterward**. The project owner reports owning `minemine.eth` and chose a MineMine-managed resolver record pointing at the player's ZeroDev wallet, rather than a transferable subname token. This is a player charge, separate from ZeroDev's provider usage bill. ZeroDev's [wallet docs](https://docs.zerodev.app/wallets) describe app-side usage credits; its [smart routing address](https://docs.zerodev.app/onramp/smart-routing-address) is a separate fiat-onramp concept. Use a hosted payment provider and verified server-side fulfillment for the name reservation. There is no separate signup charge. Do not collect card numbers in MineMine or enroll in a paid provider plan until the test flow and budget are reviewed. The existing $10/month cap is for the first DigitalOcean host, not proof that payments, ZeroDev or ENS transactions fit it.

Custom MineMine usernames for the ZeroDev signup path and wallet users need **one server-owned registry**, so a card buyer and a verified ENS wallet cannot both claim the same bare MineMine handle. Store normalized handles, account ownership, checkout holds, paid reservations and audit history outside the web root, and back them up with the world. A wallet may still display its full verified ENS name when its bare label is unavailable. The native character's wallet-derived identifier remains the authorization key. Name changes must update display in the web UI and native nametag without changing inventories, player files or town ownership. A code or name reservation must not by itself prove wallet or ZeroDev identity. The detailed [paid-name and collision design](PAID_NAMES.md) covers the `$2` checkout, `minemine.eth` control gate, managed-name rights and failure states.

### Local ZeroDev email-code lab

The isolated `/account/` page uses the documented ZeroDev Wallet hooks for email OTP, its Wagmi `7702` Sepolia connector, and Wagmi message signing. The existing MineMine SIWE challenge and smart-signature verifier then establish the server session; the page never collects a password or card number. `npm run account:build` creates the ignored browser bundle before local use or host packaging. ZeroDev/React/Wagmi are build-time dependencies, so the 1 GiB host installs only the produced static asset.

The lab is disabled unless `ZERODEV_TEST_SIGNUP=true`, a public ZeroDev project ID and a Sepolia RPC are configured. Configuration rejects the flag on a non-local origin or with shared-world launch enabled. The default loader does not download the 1.2 MB SDK bundle. A dummy-project desktop/mobile Chromium smoke verifies the form and disabled state, **not** code delivery, ZeroDev account creation, signature acceptance, recovery, or wallet transactions. A real project must allowlist the exact local origin before testing. A separate loopback Stripe test flag exposes the handle checkout form; no real charge, ENS issuance or paid account has been verified.

ZeroDev's [passkey guidance](https://docs.zerodev.app/wallets/auth/passkeys) says the relying-party ID is normally the registration hostname and changing it later generally requires a new passkey. Since MineMine's domain purchase is deferred, use [email OTP](https://docs.zerodev.app/wallets/auth/email-otp) for the first temporary-host integration and decide the permanent passkey RP ID before any real passkey registration. This is a portability decision for the technical alpha, not a promise that email alone provides sufficient account recovery. Keep any ZeroDev account provisional until the $2 order, managed-name rights, and billing/refund rules are complete.

Direct `username.minemine.eth` ENS selections now consult that shared local handle registry. A held handle cannot be displayed on another account, and a selected direct subname blocks a conflicting admin hold or checkout hold. This covers the local API and current verified reverse-name display; paid issuance still requires onchain checks and the owner's resolver setup.

MineMine-managed paid names use a different proof from wallet-owned ENS aliases. After a matching paid order, an internal activation method requires a mainnet address-record readback to the account wallet; `paid_active` is then durable. The identity path rechecks forward resolution before showing that name or placing it into a native join ticket, hiding it during an outage or after a changed record. This does not grant the player ENS ownership. Existing local registry files migrate atomically to the new state, and a cold-backup drill restores an active record. Activation is not exposed as a player API. The player checkout route is limited to a local test lab; onchain writes and the actual ZeroDev signup remain to be connected.

A separate Stripe test-mode Checkout service creates fixed-price, account-bound $2 sessions and accepts signed raw-body webhooks at `/api/stripe/webhook` only when both test secrets are configured. The webhook re-fetches the session and checks payment status, amount, currency, metadata and line item before moving a matching local hold to `paid_pending_ens`; terminal unpaid expiry can release it. A signed player can call `POST /api/names/checkout` with `{ "handle": "builder" }` only when `NAME_CHECKOUT_TEST_ENABLED=true`, Stripe test credentials are configured, and the public origin and bind address are loopback. The local ZeroDev account page offers a handle form with first-year and managed-name terms when this flag is active; it shows the Stripe test URL only after the signed server route succeeds. The endpoint derives the account from the signed cookie, reuses a durable hold and Stripe idempotency key on retry, and runs the ENS parent preflight before a hold or payment session exists. A successful response contains a Stripe-hosted test URL; it is not proof of payment or ENS issuance. The test route accepts any valid signed wallet, so it does **not** attest to a ZeroDev signup. The existing mainnet parent setup fails preflight. Real ZeroDev binding, real Stripe test-account rehearsal, renewal checkout, issuance worker, refunds and dispute handling remain release gates. Live-key support is absent.

## Admin dashboard

The `/api/admin/stats`, name-reservation and beta-code routes check the existing signed-wallet session against `ADMIN_WALLET_ADDRESSES` on every request; the empty default allows nobody. They inherit the service's per-IP rate limit and no-store policy. Creating or releasing a seven-day name hold, creating or revoking a code, and suspending or restoring an admission additionally require a signature from the last five minutes. Each transition is written to its private SQLite audit table. Production recovery controls remain. A hidden navigation link is insufficient authorization. Keep admin secrets outside the public bundle. Future smart-account admins need the same contract-signature validation as players before being allowlisted.

**Metrics:** the first implementation writes native join logs by UTC month and an atomic current-player snapshot from the wallet-auth mod. `/api/admin/stats` reads only a fresh snapshot while the native heartbeat is live and counts distinct stable character IDs with at least one accepted join in the current UTC day, Monday-start week and calendar month. It returns the period starts and earliest scanned join. Browser sessions and page views do not count. Unit tests cover UTC boundaries, deduplication and stale presence. Native run [41331833005](https://github.com/cupOJoseph/minemine/actions/runs/41331833005) passed two browser wallets in the world and saved a real snapshot with two daily/weekly/monthly active characters and one currently connected. Later work must add retention/rotation, long-world measurement and a clear collection-start marker before presenting lifetime statistics.

**Player explorer:** `/api/admin/players` searches stable character IDs or an exact signed wallet address with 25-row server pagination and a rolling 12-month accepted-join window. It shows first/last join, count and the wallet address recorded after a signed login; an older join without a profile remains visibly unlinked. The private name-registry database keeps the wallet-to-character mapping across restarts and cold backups. An admin can inspect one profile for its full signed wallet, first/last sign-in and a currently rechecked ENS display name. Non-admin HTTP requests to the profile route are denied. [Native run 41478929618](https://github.com/cupOJoseph/minemine/actions/runs/41478929618) passed the desktop/mobile profile panel and full two-wallet world sequence on the same code head; local backup restoration retained the wallet mapping. This is wallet identity, not proof of an active game session or ZeroDev signup. Exact public-username and full-ENS search now resolve through the private registry and recheck the current display before returning a character; a pending paid name, transferred ENS alias or changed managed address produces no match. Account type, town membership, admission/revocation and production retention rules remain. Never expose private grants, balances or purchase details through the explorer.

**Beta codes and reserved names:** the admin can create a code with a 1–30 day expiry, 1–100 total uses and optional intended wallet address; list uses and revoke it. The 192-bit secret is shown only in the creation response and stored as a SHA-256 hash. A signed wallet redeems it atomically into a durable account admission; repeating redemption for the same account does not consume another use. Revoking a code stops new redemptions but does not eject players already admitted. The player profile now exposes admission state and can suspend or restore that wallet's admission. Suspension is durable and cannot be bypassed by redeeming another code. With the beta gate enabled, it denies new tickets and WSS links, closes existing proxy links, and removes the native grant; the wallet-auth mod checks grant removal every two seconds and kicks the player. Admin wallets bypass the beta gate and cannot be suspended through this control. When the gate is off, the recorded state still changes but play remains open. The private audit tables record name and invite transitions, with admission events targeted to the affected wallet. The admin-only `/api/admin/audit` and dashboard show the latest 50 combined events with item ID or wallet, action, actor and UTC time, never an invite secret. The admin's name reservations, card-checkout holds and verified ENS handle claims use the **same atomic name registry**. Admin name holds have a seven-day expiry and can optionally target one validated wallet address; the admin API and dashboard show the intended account. Claiming an assigned name through player signup still needs identity and UI work. Tests cover code expiry, revocation, limits, collision, case folding, restart, and access boundaries. `BETA_INVITES_ENABLED` defaults off; when enabled, the game-ticket and WSS bridge require an admission or allowlisted admin wallet. The solo playtest remains accessible. Browser and remote-host rehearsal remain before enabling the gate publicly.

## Delivery order

1. Verify the owner's reported control of `minemine.eth` and its managed-record write permissions; the `$2` covers signup and the first managed-name year, with renewal afterward. Set the renewal price, grace and dispute terms before any charge. Start with ZeroDev Wallet `7702` on Sepolia. Review current provider limits and costs; use only test projects for the first integration.
2. Add durable native presence events and UTC active-player aggregates; build read-only admin metrics against a disposable world and exercise restarts.
3. Add admin authorization, audit log, beta-code lifecycle and a durable normalized username/reservation registry; test concurrent redemption and name claims.
4. Add the wallet signup screen with verified ENS ownership selection and transfer/revocation handling. Keep native IDs unchanged. Add custom username selection for ZeroDev accounts.
5. Add ZeroDev signup and smart-signature verification, then test a funded testnet account's MINE transfer and paid town claim. Implement hosted `$2` name checkout, verified idempotent fulfillment and ENS issuance only after parent control, managed-name rights, renewal price, grace and refund rules are settled.
6. Build the player explorer and admin dashboard UI on top of tested APIs; verify non-admin denial, mobile layout, accessibility and production-data migration/backup behavior.

`/admin.html` renders current and UTC day/week/month counts, current stable character IDs, a freshness warning and the recent player explorer from allowlisted APIs. It has signed-wallet profile inspection plus controls to create/release seven-day local name holds and create/list/revoke beta codes. The wallet panel accepts a code for the current signed-in address when invite mode is enabled. An admin signs in with the configured wallet on the main page first; the empty allowlist grants nobody. [Native run 41374795081](https://github.com/cupOJoseph/minemine/actions/runs/41374795081) passed a mocked-API Chromium desktop/mobile smoke for the new admin controls, including create, release and revoke interactions, with screenshots in the run artifact. The name checkout and ZeroDev account lab are confined to local test flags.
