# Paid MineMine names and collision policy

Research checked 2026-11-01. Product intent: a player using the conventional email/passkey and credit-card signup path pays **$2 USD to reserve `username.mine.eth`**. Whether the account itself has a separate price is not yet specified. The account is backed by a ZeroDev smart wallet; it is not a wallet-extension signup. An existing-wallet player can instead sign in with a wallet and choose an ENS name they currently own. No paid checkout, name registry or ENS subname issuance is live yet.

## The one-name rule

Keep **one authoritative MineMine handle registry** for both signup paths. Normalize the requested bare handle before a hold or claim; the proposed first version accepts lowercase ASCII letters followed by 2–15 lowercase letters or digits (`^[a-z][a-z0-9]{2,15}$`). Case variants resolve to one handle. Reserve product/admin/system words. A handle is either available, held for a specific checkout until a short deadline, paid and bound to one account, claimed by a verified wallet user, or administratively reserved. A transaction must make the availability check and state change atomic. The stable Luanti character key remains the wallet-derived internal ID; a handle or ENS change cannot move another player's inventory or town.

An external-wallet player may display a **fully qualified, verified ENS name** such as `alice.eth`, even when another account has the MineMine handle `alice`; never silently shorten it to `alice`. If the wallet player requests the bare MineMine handle `alice`, it must pass the same registry check as a paid signup. In particular, `alice.mine.eth` and a paid request for `alice` refer to the same `alice` namespace entry and cannot be assigned to different accounts. A reverse ENS name or address record is not ownership proof. Recheck current ownership when an ENS alias is bound and after transfers/expiry. A preexisting onchain owner of the exact `alice.mine.eth` name also blocks a paid sale; the local registry cannot override ENS.

## What the $2 purchase must mean

An ENS subname can be either a project-managed record or a separately owned token. [ENSv2's subname guide](https://docs.ens.domains/ensv2/subnames/) explicitly distinguishes resolver records controlled by the parent from UserRegistry subname tokens with separate owners and roles. The older [Name Wrapper registrar guide](https://docs.ens.domains/wrapper/creating-subname-registrar/) says new projects should use ENSv2 rather than start on the ENSv1 wrapper. We need the parent owner to authorize the chosen issuance route. A read-only mainnet query at block 26321682 found `mine.eth` registered in the ENSv1 registry, with registry owner `0x6359EF876d6F82F669709950bb2c8e19b8e82481`; that does **not** establish that MineMine controls the name or the ENSv2 roles. Verify parent control with the owner's wallet before taking money or advertising this name.

The initial product proposal is a **MineMine-managed subname**, pointed at the player's ZeroDev wallet, with the account's use of the name explained in the purchase terms. If players should own a transferable ENS token, use an ENSv2 UserRegistry and price/renewal/fraud policy appropriate to that right. Do not call a database hold “ENS ownership” or show `username.mine.eth` as active until the authoritative ENS lookup resolves as intended. Decide whether the $2 is for the account, the name, or both; whether the name lasts while the account remains active or for a fixed term; and what happens if the parent expires, the account is banned, a payment is refunded or disputed, or ENS issuance fails.

## Checkout and fulfillment sequence

1. Establish a recoverable ZeroDev account identity and its stable smart-wallet address. Reserve a unique handle with a short, account-bound checkout hold. Check the exact ENS subname and parent permissions before offering payment. Admin reservations and verified ENS claims use the same collision check.
2. Create a server-priced **$2 USD, one-time** hosted Checkout Session with an order ID bound to that hold and account. The browser cannot set the price, account ID or selected handle. MineMine never receives card numbers. A hold expires if payment is abandoned; it cannot be recycled while a payment may still complete without a reconciliation check.
3. Fulfill only after a verified payment event. [Stripe's fulfillment guide](https://docs.stripe.com/checkout/fulfillment.md?ui=full-page) requires server-side fulfillment and handling duplicate events; a success-page redirect is not proof of payment. Verify the webhook signature using the raw body, retrieve or validate the Checkout Session, require paid status and the exact `usd`/`200` amount, and atomically record the session/payment ID once. Handle delayed success, expiry, failure, duplicate delivery and out-of-order events.
4. Move the hold to a **paid reservation** bound to the account. Queue ENS issuance or record update, then verify the resulting name onchain before showing it as active. Keep an explicit `paid_pending_ens` state so an onchain or provider failure cannot be mistaken for completion. Retry safely or refund/offer a different name if fulfillment cannot succeed. Audit every transition and admin override.
5. Test two simultaneous checkouts for the same handle, payment after hold expiry, webhook replay, server restart/restore, ENS ownership transfer, parent expiry, ZeroDev recovery, chargebacks, and alias changes. The beta invite gate remains a separate requirement; the $2 purchase should not accidentally bypass a closed beta unless that is a deliberate policy.

[Stripe's current US standard pricing](https://stripe.com/pricing) lists 2.9% + 30¢ per successful domestic card payment. On a $2 charge that is about **36¢ in processing fees**, leaving about **$1.64 before ENS transaction gas, ZeroDev usage, taxes, refunds and disputes**. This is a feasibility estimate, not an approved profit margin or a guarantee of the final fee. The project's first VPS budget remains capped at $10/month; payment processing and ENS costs need their own test and budget decision. Use test-mode checkout and a disposable ENS test parent before any live purchase.

## Release gates

- Confirm MineMine can control `mine.eth`, or switch to a parent name it controls. No sale of `*.mine.eth` before that proof.
- Choose managed record versus player-owned token, duration/renewal, refund and dispute policy. Check ENSv2 deployment support on the chosen chain and the actual gas cost.
- Obtain and configure a payment-provider test account and ZeroDev test project. Keep keys server-side and out of the repository.
- Implement and test the shared registry, account binding, hosted checkout, verified idempotent fulfillment and onchain issuance. Show a clear pending state if ENS has not been issued yet.
