# VPS recommendation for the first MineMine online alpha

Revised 2026-10-23 for the owner's **$10/month maximum** and decision to defer buying `minemine.gg`. This is a proposed technical alpha, not a purchased server or a claim that an MMO fits this size.

## Recommended first public test host

Use one [DigitalOcean Basic Droplet](https://www.digitalocean.com/pricing/droplets) in `nyc3` (New York City) with **1 shared vCPU, 1 GiB RAM, 25 GiB SSD, and 1,000 GiB bundled monthly transfer**. DigitalOcean lists it at **$6/month**. [Daily automated backups](https://docs.digitalocean.com/products/backups/details/pricing/) add 30%, or **$1.80/month**, for a **$7.80/month listed base**. The $2.20 difference to the budget covers only taxes and any incidental usage; it is not guaranteed headroom. Do not add paid volumes, snapshots, monitoring products, or a domain during this phase. [Basic Droplets are available in NYC3](https://docs.digitalocean.com/platform/regional-availability/).

**Capacity is unproven.** One GiB must accommodate Linux, Luanti, Node, the reverse proxy, and a small persistent world. The only justified initial audience is an invite-only technical alpha with a low connection cap, after a memory-limited rehearsal and remote two-player test pass. Benchmark tick time, memory, CPU and egress before increasing the cap. Sixteen concurrent players and SpacetimeDB are later milestones, outside this host's demonstrated capacity and likely outside this budget.

[Native Actions run 39844611581](https://github.com/cupOJoseph/minemine/actions/runs/39844611581) provides a first **process-memory baseline** for the two-wallet Chromium smoke test on an Ubuntu 22.04 runner. One-second samples recorded a peak combined Luanti + Node resident set size of **208.1 MiB** across 208 samples during the first world session, and **165.7 MiB** across 37 samples after a clean Luanti/Node restart. The first-session individual peaks were 107.3 MiB for Luanti and 100.8 MiB for Node. The browser ran on the CI machine but would run on players' devices in production. These figures exclude the VM operating system, Caddy, filesystem cache, build/deploy work, a growing world, and longer or heavier player load. RSS sampling can miss brief peaks and counts shared pages in both processes. The runner had more than 1 GiB available; this is **not** a successful 1 GiB limit test or proof that the proposed Droplet can host a public world.

[Capped Actions run 39855175363](https://github.com/cupOJoseph/minemine/actions/runs/39855175363) then passed two-wallet browser protection, a forced connected-player ticket-expiry check, reconnect, and restart with **Luanti and Node in a shared 1 GiB systemd cgroup and zero swap**. The verified cgroup peak was 188,555,264 bytes (179.8 MiB) through the first world session and unchanged after restart, with zero OOM events/kills. Combined process RSS peaked at 242.1 MiB during the first session. This is evidence that the *two services* handled this short workload under the memory limit; the Chromium clients ran outside it, and the operating system, Caddy, disk cache outside that slice, world growth, and sustained load are not covered. A whole-VM rehearsal and remote network test remain gates before calling the $6 Droplet viable.

[Actions run 39892709610](https://github.com/cupOJoseph/minemine/actions/runs/39892709610) passed the full local two-wallet native test, heartbeat readiness, expired-ticket auth lookup, reconnect and restart. It produced a **tested Ubuntu 22.04 x86-64 host archive** (`minemine-host-runtime-ubuntu22-x64`, 18 MB compressed) with the run-in-place native binary, its game files, the verified browser engine/adapter, Node source and package lock, and service templates. CI checked the archive checksum, unpacked it at a different path, and started the relocated native world with both mods. The example archive SHA-256 is `f28a0de3a3982d04311958507041dadc6a19eafaacdd8bf7303bd7f0ea507fd7`. It is tied to the exact CI checkout recorded in `BUILD_COMMIT`; later builds need their own checksum. This removes compilation and WASM staging from the proposed 1 GiB host. It does not test a full 1 GiB VM, target library installation, Caddy, or an outside-network browser.

[Final candidate run 39915834630](https://github.com/cupOJoseph/minemine/actions/runs/39915834630) repeated the two-wallet, town-protection, expired-ticket, reconnect and restart checks with the upgraded browser engine and a six-mapblock native send/generation cap. Its shared 1 GiB, zero-swap Luanti/Node service cgroup peaked at 143,671,296 bytes, with zero OOM kills; browser clients and the operating system were outside the cap. The new 18 MB host archive includes the final browser release and checked SHA-256 `d045f1007ae02a8944f0f617862eda656c1839e7f7b1d6537ee2ca5db4363d87`. One preceding run missed a synthetic dig input under heavy map delivery, then passed unchanged on rerun; longer reliability testing remains necessary. This archive is the current deployment candidate, but it has not run on a full 1 GiB Droplet or outside-network browser.

DigitalOcean's [spend alerts](https://docs.digitalocean.com/platform/billing/spend-alerts/) are **not hard spending caps**; tax and [outbound transfer beyond the allowance](https://docs.digitalocean.com/platform/billing/bandwidth/) can make the bill exceed $10. Set a total-spend alert below $10 and monitor transfer, but treat the strict ceiling as a provisioning gate: if the account's tax or other unavoidable charges remove the $2.20 margin, do not create the Droplet. The 2 GiB Basic plan is listed at $12/month before backups, so it does not meet the limit.

## Single-host layout

1. Serve the MineMine landing, `/play/` browser bundle, wallet/API endpoints, and `/game-proxy` from one HTTPS origin behind a TLS reverse proxy. Preserve Host and WebSocket upgrade headers and the engine's COOP/COEP isolation headers. For the technical alpha, use a temporary HTTPS address; buying `minemine.gg` waits for demonstrated viability and public interest. The current Pages deployment remains the solo playtest until the public stack is ready.
2. Run one Node service bound to `127.0.0.1:3000`, one native Luanti server bound to `127.0.0.1:30000/udp`, and one persistent SQLite-backed world. Expose SSH, HTTPS 443, and HTTP 80 for [automatic TLS certificate issuance and redirects](https://caddyserver.com/docs/quick-starts/https) at the VM firewall; keep Node and native UDP private. The browser's `10.0.0.1` address is virtual; the Node bridge sends only to the loopback game port.
3. Use a dedicated unprivileged service account for Node and Luanti so the private `wallet_grants` and `town_quotas` directories can be shared without putting them under the web root. Keep one Node process until sessions and grants have durable coordination.
4. Enable daily provider backups and a separate application-level stopped-world backup with a tested restore. Provider disk images alone do not demonstrate an application-consistent SQLite restore. Retain build manifests and private configuration separately from the world.
5. Begin with one region and no load balancer, paid CDN, or SpacetimeDB node. Increase the player cap only after measured remote-browser behavior and resource use support it.

## Prepared host configuration

The repository includes a [Caddyfile example](../deploy/vps/Caddyfile.example) and separate [web](../deploy/vps/minemine-web.service) and [native](../deploy/vps/minemine-native.service) systemd units. They assume an Ubuntu **22.04 x86-64** VM with a dedicated `minemine` user, the reviewed archive extracted at `/srv/minemine/app`, the world at `/srv/minemine/world`, Node 24 at `/usr/bin/node`, and the pinned run-in-place Luanti binary at `/srv/minemine/app/vendor/native/bin/luantiserver`. The [native game config](../game/minetest.conf) caps the technical alpha at two concurrent players and six-mapblock send/generation radii; raise these only after measuring the actual host. The current [native CI workflow](../.github/workflows/native-smoke.yml) builds and tests the portable archive. These templates have not been run on a public host.

After the account owner connects DigitalOcean and a temporary HTTPS host has been selected:

1. Download the `minemine-host-runtime-ubuntu22-x64` artifact from a successful reviewed native CI run to a trusted workstation, verify its `.sha256` sidecar, then copy both files to the VM and verify again before extraction into `/srv/minemine/app`. Keep `BUILD_COMMIT`, `public/engine/build.json`, and the asset hashes. Do not run the native or WASM compiler on this 1 GiB host. Install Node 24 and native runtime libraries for Ubuntu 22.04; run `ldd /srv/minemine/app/vendor/native/bin/luantiserver` and resolve every `not found` entry against the archive's `native-library-dependencies.txt` before starting services. Run `npm ci --omit=dev` in the extracted app. Create the `minemine` OS user and private world directory, then run `WORLD_DIR=/srv/minemine/world node scripts/setup-world.mjs` from `/srv/minemine/app` as that user. The archive contains no world or wallet grants. The full transfer and service sequence is in [DEPLOYMENT.md](DEPLOYMENT.md#6-host-the-tested-stack).
2. Create `/etc/minemine/minemine.env`, readable by the service user but not the public web server. Set `HOST=127.0.0.1`, `PORT=3000`, `PUBLIC_ORIGIN` to the exact temporary HTTPS origin, `WORLD_DIR=/srv/minemine/world`, and the reviewed chain/RPC settings. Leave `GAME_ENABLED=false` and `ENGINE_ADAPTER_READY=false` until the external-browser and authorization checks pass. Keep deployment private keys out of this service file.
3. Install both unit files under `/etc/systemd/system/`, run `systemctl daemon-reload`, and start the native and web units. Confirm each service stays active and `/api/health` reports `nativeReady: true` with the expected Host header. `nativeReady` requires a heartbeat written by the Luanti world within ten seconds; it does not prove that native UDP is reachable through the browser proxy. With the launch flags still false, `gameReady` must remain false. Set the flags true only for a controlled outside-network two-wallet rehearsal, then leave the shared-world button gated until its authorization, recovery and resource checks pass.
4. Replace the host placeholder in the Caddyfile with the temporary hostname, validate it with `caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile`, then start Caddy. Caddy's [automatic HTTPS](https://caddyserver.com/docs/quick-starts/https) requires working DNS and public ports 80 and 443; its [reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) forwards WebSocket upgrades. A free IP-derived hostname such as `play.<public-ip>.sslip.io` is an option for a disposable test, but it depends on a third-party DNS operator; use it only after verifying DNS and certificate issuance. [Let's Encrypt also issues short-lived IP certificates](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability), which could avoid third-party DNS with a separate automated certificate setup. Neither route is assumed working until tested on the provisioned host. Confirm `crossOriginIsolated`, WSS, and external joins.
5. Test a clean native restart and a stopped-world backup/restore before enabling the shared-world button. Record service and Caddy logs, CPU, RAM, disk and network use during the first load test. The VPS firewall should expose only 80/443 and narrowly scoped SSH; do not expose ports 3000 or 30000.

## Provisioning and launch gates

The owner has a DigitalOcean account and has selected a maximum of $10/month, but will connect the account when deployment is ready. No VM, domain, DNS record, testnet token, or paid service has been created. At connection time, verify the exact plan, region, tax treatment and projected total against the limit, then obtain SSH access through an approved secure channel. A purchased domain is **not** a prerequisite for the technical alpha.

Before enabling the shared-world button or announcing the URL, verify:

- The deployment uses the credential-safe WASM artifact and hash-checked static assets; TLS, WSS, COOP/COEP and browser features work from an outside network.
- Two distinct wallet browsers join the public world, see each other's edits, reconnect to the same character and inventory, and cannot register or elevate privilege outside wallet auth.
- Town quotas reflect confirmed testnet purchases; owner/member/outsider dig and place behavior survives restart.
- Automated backups, a stopped-world restore, process restarts, log/metric collection, disk alerts, and a small invite-only load test pass with recorded CPU, RAM, tick time and egress. The 16-client target requires separate capacity measurement and may require a larger future budget.

This host recommendation is for the first native-server milestone. The [SpacetimeDB plan](SPACETIMEDB.md) is a later architecture decision after native-world measurements.
